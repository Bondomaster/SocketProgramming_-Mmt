# HƯỚNG DẪN KIỂM THỬ 12 TIÊU CHÍ (Kèm Câu Lệnh Chi Tiết Từ HOW_TO_RUN)

Tài liệu này cung cấp từng câu lệnh cụ thể, **bám sát 100% các lệnh hỗ trợ trong file HOW_TO_RUN.txt** để bạn chạy demo trực tiếp cho 12 tiêu chí.

---

### Môi trường chuẩn bị chung
Mở Terminal (PowerShell) và chuyển vào thư mục dự án:
```bash
cd hybrid-ftp
```

---

### Tiêu chí 1: Phân tách chức năng giữa TCP và UDP
**Terminal 1 (Server):**
```bash
python -m server.main --port 2121 --root ./ftp_root
```
**Terminal 2 (Client):**
```bash
python -m client.main --port 2121
```
Đăng nhập và gửi các lệnh TCP (Control):
```ftp
ftp> USER admin
ftp> PASS 1234
ftp> SYST
ftp> STAT
ftp> HELP
ftp> NOOP
```
Gửi lệnh tải file (Mở kênh UDP Data truyền dữ liệu qua Stop-and-Wait):
```ftp
ftp> STOR sample.txt
```

---

### Tiêu chí 2: Tính tin cậy của cơ chế Stop-and-Wait (Mất gói & Retransmit)
**Terminal 2 (Thoát Client bằng lệnh `QUIT`, sau đó mở lại với thông số drop-rate):**
```bash
python -m client.main --port 2121 --drop-rate 0.3
```
Bên trong FTP Prompt:
```ftp
ftp> USER admin
ftp> PASS 1234
ftp> STOR sample.txt
```
*Quan sát: Thanh tiến trình chậm lại, hệ thống hiển thị thông báo "retransmit" do gói tin mất trên đường truyền.*

---

### Tiêu chí 3: Tính đúng thứ tự của dữ liệu
Truyền file mẫu lên server và tải ngược về:
```ftp
ftp> STOR sample.txt
ftp> RETR sample.txt
```
*Giải thích: Mọi dữ liệu (dù bị rớt/retransmit) vẫn luôn ghi ra file theo đúng thứ tự (Sequence Number 0 và 1 luân phiên của RDT Stop-and-wait).*

---

### Tiêu chí 4: Phát hiện lỗi dữ liệu (Checksum CRC32)
**Terminal 2 (Thoát Client, mở lại với thông số corrupt-rate):**
```bash
python -m client.main --port 2121 --corrupt-rate 0.2
```
Bên trong FTP Prompt:
```ftp
ftp> USER admin
ftp> PASS 1234
ftp> STOR sample.txt
```
*Quan sát: Sender cố tình làm hỏng gói tin. Server phát hiện CRC32 sai, drop gói, bắt buộc Sender timeout và truyền lại gói đúng.*

---

### Tiêu chí 5: Xử lý gói tin trùng lặp
**Terminal 2 (Chạy kết hợp drop và corrupt để tỉ lệ rơi rớt ACK cao):**
```bash
python -m client.main --port 2121 --drop-rate 0.2 --corrupt-rate 0.1
```
```ftp
ftp> USER admin
ftp> PASS 1234
ftp> STOR sample.txt
```
*Quan sát: Khi ACK từ Server bị mất, Client gửi lại gói dữ liệu vừa gửi. Server nhận ra Sequence Number bị trùng, từ chối ghi dữ liệu vào file nhưng vẫn trả về ACK để thông nghẽn.*

---

### Tiêu chí 6: Tính toàn vẹn của file
Sử dụng các lệnh xem thông tin file để kiểm chứng:
```ftp
ftp> SIZE sample.txt
ftp> MDTM sample.txt
```
*Quan sát: Lệnh SIZE trả về số bytes chính xác bằng với kích thước của `sample.txt` trên máy bạn.*

---

### Tiêu chí 7: Khả năng truyền file đa dạng
Chuyển đổi các chế độ Type và thử các kiểu Upload RDT:
```ftp
# Chuyển sang ASCII mode (Truyền văn bản)
ftp> TYPE A
ftp> STOR sample.txt

# Chuyển sang Binary mode (Truyền nhị phân, ảnh, v.v...)
ftp> TYPE I
ftp> STOR sample.txt

# Upload nối tiếp vào cuối file trên server
ftp> APPE sample.txt

# Upload với tên duy nhất (Server tự sinh tên)
ftp> STOU sample.txt
```

---

### Tiêu chí 8: Chống Path Traversal
Cố gắng vượt quyền truy cập thư mục gốc `ftp_root`:
```ftp
ftp> CWD ../
ftp> RETR ../../Windows/System32
```
*Kết quả: Server từ chối lệnh, bảo vệ an toàn thư mục gốc.*

---

### Tiêu chí 9: Điều hướng và quản lý thư mục/tệp tin
Áp dụng đúng các lệnh Advanced Level trong `HOW_TO_RUN`:
```ftp
ftp> MKD test_folder
ftp> CWD test_folder
ftp> PWD
ftp> CDUP
ftp> RMD test_folder

# Liệt kê
ftp> LIST
ftp> NLST

# Đổi tên và xoá
ftp> STOR sample.txt
ftp> RNFR sample.txt
ftp> RNTO new_name.txt
ftp> DELE new_name.txt
```

---

### Tiêu chí 10: Chuyển đổi Active/Passive Mode
Chuyển đổi luân phiên để chứng minh Client/Server đáp ứng tốt:
```ftp
# Sử dụng Passive Mode (Mở UDP ngẫu nhiên)
ftp> PASV
ftp> LIST

# Sử dụng Active Mode (Server gọi ngược lại Client)
ftp> PORT
ftp> LIST
```

---

### Tiêu chí 11: Đa luồng và cô lập phiên (Concurrency Control)
Mở thêm **Terminal 3** chạy Client thứ hai:
```bash
python -m client.main --port 2121
```
Bên Terminal 2 đang dùng tài khoản `admin`:
```ftp
ftp> STOR sample.txt
```
Trong khi Terminal 2 đang truyền file, tại Terminal 3 đăng nhập tài khoản khác:
```ftp
ftp> USER alice
ftp> PASS secret
ftp> LIST
```
*Quan sát: Server phản hồi luồng của `alice` độc lập và ngay tức khắc, không bị chờ luồng `admin` truyền xong.*

---

### Tiêu chí 12: Khả năng xử lý lỗi và kết thúc phiên
**Timeout do không có dữ liệu / Ngắt ngang:**
```ftp
ftp> STOR sample.txt
```
Lập tức nhấn `Ctrl + C` ở cửa sổ Client 2. 
*Quan sát Terminal 1 (Server): Server không bị sập. Khoảng một thời gian ngắn sau, thread phục vụ Client 2 sẽ nhận diện Timeout (Connection closed; transfer aborted) và tự dọn dẹp.*

**Đóng phiên thông thường (Tại Terminal 3):**
```ftp
ftp> QUIT
```
*Thoát sạch sẽ, trả về mã trạng thái kết thúc.*

### Tiêu chí 2: Tính tin cậy của cơ chế Stop-and-Wait (Mất gói & Retransmit)
**Terminal 2 (Thoát Client bằng lệnh `QUIT`, sau đó mở lại với thông số drop-rate):**
```bash
python -m client.main --port 2121 --drop-rate 0.3
```
Bên trong FTP Prompt:
```ftp
ftp> USER admin
ftp> PASS 1234
ftp> STOR sample.txt
```
*Quan sát: Thanh tiến trình chậm lại, hệ thống hiển thị thông báo "retransmit" do gói tin mất trên đường truyền.*

---

### Tiêu chí 3: Tính đúng thứ tự của dữ liệu
Truyền file mẫu lên server và tải ngược về:
```ftp
ftp> STOR sample.txt
ftp> RETR sample.txt
```
*Giải thích: Mọi dữ liệu (dù bị rớt/retransmit) vẫn luôn ghi ra file theo đúng thứ tự (Sequence Number 0 và 1 luân phiên của RDT Stop-and-wait).*

---

### Tiêu chí 4: Phát hiện lỗi dữ liệu (Checksum CRC32)
**Terminal 2 (Thoát Client, mở lại với thông số corrupt-rate):**
```bash
python -m client.main --port 2121 --corrupt-rate 0.2
```
Bên trong FTP Prompt:
```ftp
ftp> USER admin
ftp> PASS 1234
ftp> STOR sample.txt
```
*Quan sát: Sender cố tình làm hỏng gói tin. Server phát hiện CRC32 sai, drop gói, bắt buộc Sender timeout và truyền lại gói đúng.*

---

### Tiêu chí 5: Xử lý gói tin trùng lặp
**Terminal 2 (Chạy kết hợp drop và corrupt để tỉ lệ rơi rớt ACK cao):**
```bash
python -m client.main --port 2121 --drop-rate 0.2 --corrupt-rate 0.1
```
```ftp
ftp> USER admin
ftp> PASS 1234
ftp> STOR sample.txt
```
*Quan sát: Khi ACK từ Server bị mất, Client gửi lại gói dữ liệu vừa gửi. Server nhận ra Sequence Number bị trùng, từ chối ghi dữ liệu vào file nhưng vẫn trả về ACK để thông nghẽn.*

---

### Tiêu chí 6: Tính toàn vẹn của file
Sử dụng các lệnh xem thông tin file để kiểm chứng:
```ftp
ftp> SIZE sample.txt
ftp> MDTM sample.txt
```
*Quan sát: Lệnh SIZE trả về số bytes chính xác bằng với kích thước của `sample.txt` trên máy bạn.*

### Tiêu chí 7: Khả năng truyền file đa dạng

ftp> APPE sample.txt

# Upload với tên duy nhất (Server tự sinh tên)
ftp> STOU sample.txt
```

### Tiêu chí 8: Chống Path Traversal

```
*Kết quả: Server từ chối lệnh, bảo vệ an toàn thư mục gốc.*

### Tiêu chí 9: Điều hướng và quản lý thư mục/tệp tin

ftp> LIST

# Sử dụng Active Mode (Server gọi ngược lại Client)
ftp> PORT
ftp> LIST
```

---

### Tiêu chí 11: Đa luồng và cô lập phiên (Concurrency Control)
Mở thêm **Terminal 3** chạy Client thứ hai:
```bash

```
Bên Terminal 2 đang dùng tài khoản `admin`:
```ftp
ftp> STOR sample.txt
```
Trong khi Terminal 2 đang truyền file, tại Terminal 3 đăng nhập tài khoản khác:
```ftp
ftp> USER alice
ftp> PASS secret
ftp> LIST
```
*Quan sát: Server phản hồi luồng của `alice` độc lập và ngay tức khắc, không bị chờ luồng `admin` truyền xong.*

### Tiêu chí 12: Khả năng xử lý lỗi và kết thúc phiên
**Timeout do không có dữ liệu / Ngắt ngang:**
```ftp

```
Lập tức nhấn `Ctrl + C` ở cửa sổ Client 2. 
*Quan sát Terminal 1 (Server): Server không bị sập. Khoảng một thời gian ngắn sau, thread phục vụ Client 2 sẽ nhận diện Timeout (Connection closed; transfer aborted) và tự dọn dẹp.*

**Đóng phiên thông thường (Tại Terminal 3):**
```ftp
ftp> QUIT
```
*Thoát sạch sẽ, trả về mã trạng thái kết thúc.*

python -m client.main --port 2121 --corrupt-rate 0.2
```
Bên trong FTP Prompt:
```ftp

*Quan sát: Sender cố tình làm hỏng gói tin. Server phát hiện CRC32 sai, drop gói, bắt buộc Sender timeout và truyền lại gói đúng.*

### Tiêu chí 5: Xử lý gói tin trùng lặp
**Terminal 2 (Chạy kết hợp drop và corrupt để tỉ lệ rơi rớt ACK cao):**

python -m client.main --port 2121 --drop-rate 0.2 --corrupt-rate 0.1
```
```ftp
ftp> USER admin
ftp> PASS 1234
ftp> STOR sample.txt

*Quan sát: Khi ACK từ Server bị mất, Client gửi lại gói dữ liệu vừa gửi. Server nhận ra Sequence Number bị trùng, từ chối ghi dữ liệu vào file nhưng vẫn trả về ACK để thông nghẽn.*

### Tiêu chí 6: Tính toàn vẹn của file

```ftp
ftp> SIZE sample.txt
ftp> MDTM sample.txt
```
*Quan sát: Lệnh SIZE trả về số bytes chính xác bằng với kích thước của `sample.txt` trên máy bạn.*

### Tiêu chí 7: Khả năng truyền file đa dạng

### Tiêu chí 11: Đa luồng và cô lập phiên (Concurrency Control)

Bên Terminal 2 đang dùng tài khoản `admin`:

**Terminal 1 (Server):**
```bash
python -m server.main --port 2121 --root ./ftp_root
```
**Terminal 2 (Client):**
```bash

Đăng nhập và gửi các lệnh TCP (Control):
```ftp
ftp> USER admin
ftp> PASS 1234
ftp> SYST
ftp> STAT
ftp> HELP
ftp> NOOP
```
Gửi lệnh tải file (Mở kênh UDP Data truyền dữ liệu qua Stop-and-Wait):
```ftp

```

### Tiêu chí 2: Tính tin cậy của cơ chế Stop-and-Wait (Mất gói & Retransmit)
**Terminal 2 (Thoát Client bằng lệnh `QUIT`, sau đó mở lại với thông số drop-rate):**
```bash
python -m client.main --port 2121 --drop-rate 0.3
```
Bên trong FTP Prompt:
```ftp
ftp> USER admin
ftp> PASS 1234
ftp> STOR sample.txt
```
*Quan sát: Thanh tiến trình chậm lại, hệ thống hiển thị thông báo "retransmit" do gói tin mất trên đường truyền.*

---

### Tiêu chí 3: Tính đúng thứ tự của dữ liệu
Truyền file mẫu lên server và tải ngược về:
```ftp
ftp> STOR sample.txt
ftp> RETR sample.txt
```
*Giải thích: Mọi dữ liệu (dù bị rớt/retransmit) vẫn luôn ghi ra file theo đúng thứ tự (Sequence Number 0 và 1 luân phiên của RDT Stop-and-wait).*

---

### Tiêu chí 4: Phát hiện lỗi dữ liệu (Checksum CRC32)
**Terminal 2 (Thoát Client, mở lại với thông số corrupt-rate):**
```bash
python -m client.main --port 2121 --corrupt-rate 0.2
```
Bên trong FTP Prompt:
```ftp

ftp> PASS 1234
ftp> STOR sample.txt
```
*Quan sát: Sender cố tình làm hỏng gói tin. Server phát hiện CRC32 sai, drop gói, bắt buộc Sender timeout và truyền lại gói đúng.*

---

### Tiêu chí 5: Xử lý gói tin trùng lặp
**Terminal 2 (Chạy kết hợp drop và corrupt để tỉ lệ rơi rớt ACK cao):**
```bash
python -m client.main --port 2121 --drop-rate 0.2 --corrupt-rate 0.1
```
```ftp
ftp> USER admin
ftp> PASS 1234
ftp> STOR sample.txt
```
*Quan sát: Khi ACK từ Server bị mất, Client gửi lại gói dữ liệu vừa gửi. Server nhận ra Sequence Number bị trùng, từ chối ghi dữ liệu vào file nhưng vẫn trả về ACK để thông nghẽn.*

---

ftp> MDTM sample.txt
```
*Quan sát: Lệnh SIZE trả về số bytes chính xác bằng với kích thước của `sample.txt` trên máy bạn.*

---

### Môi trường chuẩn bị chung
Mở Terminal (PowerShell) và chuyển vào thư mục dự án:
```bash
cd hybrid-ftp
```

---

### Tiêu chí 1: Phân tách chức năng giữa TCP và UDP
**Terminal 1 (Server):**
```bash
python -m server.main --port 2121 --root ./ftp_root
```
**Terminal 2 (Client):**
```bash
python -m client.main --port 2121
```
Đăng nhập và gửi các lệnh TCP (Control):
```ftp
ftp> USER admin
ftp> PASS 1234
ftp> SYST
ftp> STAT
ftp> HELP
ftp> NOOP
```
Gửi lệnh tải file (Mở kênh UDP Data truyền dữ liệu qua Stop-and-Wait):
```ftp
ftp> STOR sample.txt
```

---

### Tiêu chí 2: Tính tin cậy của cơ chế Stop-and-Wait (Mất gói & Retransmit)
**Terminal 2 (Thoát Client bằng lệnh `QUIT`, sau đó mở lại với thông số drop-rate):**
```bash
python -m client.main --port 2121 --drop-rate 0.3
```
Bên trong FTP Prompt:
```ftp
ftp> USER admin
ftp> PASS 1234
ftp> STOR sample.txt
```
*Quan sát: Thanh tiến trình chậm lại, hệ thống hiển thị thông báo "retransmit" do gói tin mất trên đường truyền.*

---

### Tiêu chí 3: Tính đúng thứ tự của dữ liệu
Truyền file mẫu lên server và tải ngược về:
```ftp
ftp> STOR sample.txt
ftp> RETR sample.txt
```
*Giải thích: Mọi dữ liệu (dù bị rớt/retransmit) vẫn luôn ghi ra file theo đúng thứ tự (Sequence Number 0 và 1 luân phiên của RDT Stop-and-wait).*

---

### Tiêu chí 4: Phát hiện lỗi dữ liệu (Checksum CRC32)
**Terminal 2 (Thoát Client, mở lại với thông số corrupt-rate):**
```bash
python -m client.main --port 2121 --corrupt-rate 0.2
```
Bên trong FTP Prompt:
```ftp
ftp> USER admin
ftp> PASS 1234
ftp> STOR sample.txt
```
*Quan sát: Sender cố tình làm hỏng gói tin. Server phát hiện CRC32 sai, drop gói, bắt buộc Sender timeout và truyền lại gói đúng.*

---

### Tiêu chí 5: Xử lý gói tin trùng lặp
**Terminal 2 (Chạy kết hợp drop và corrupt để tỉ lệ rơi rớt ACK cao):**
```bash
python -m client.main --port 2121 --drop-rate 0.2 --corrupt-rate 0.1
```
```ftp
ftp> USER admin
ftp> PASS 1234
ftp> STOR sample.txt
```
*Quan sát: Khi ACK từ Server bị mất, Client gửi lại gói dữ liệu vừa gửi. Server nhận ra Sequence Number bị trùng, từ chối ghi dữ liệu vào file nhưng vẫn trả về ACK để thông nghẽn.*

---

### Tiêu chí 6: Tính toàn vẹn của file
Sử dụng các lệnh xem thông tin file để kiểm chứng:
```ftp
ftp> SIZE sample.txt
ftp> MDTM sample.txt
```
*Quan sát: Lệnh SIZE trả về số bytes chính xác bằng với kích thước của `sample.txt` trên máy bạn.*

---

### Tiêu chí 7: Khả năng truyền file đa dạng
Chuyển đổi các chế độ Type và thử các kiểu Upload RDT:
```ftp
# Chuyển sang ASCII mode (Truyền văn bản)
ftp> TYPE A
ftp> STOR sample.txt

# Chuyển sang Binary mode (Truyền nhị phân, ảnh, v.v...)
ftp> TYPE I
ftp> STOR sample.txt

# Upload nối tiếp vào cuối file trên server
ftp> APPE sample.txt

# Upload với tên duy nhất (Server tự sinh tên)
ftp> STOU sample.txt
```

---

### Tiêu chí 8: Chống Path Traversal
Cố gắng vượt quyền truy cập thư mục gốc `ftp_root`:
```ftp
ftp> CWD ../
ftp> RETR ../../Windows/System32
```
*Kết quả: Server từ chối lệnh, bảo vệ an toàn thư mục gốc.*

---

### Tiêu chí 9: Điều hướng và quản lý thư mục/tệp tin
Áp dụng đúng các lệnh Advanced Level trong `HOW_TO_RUN`:
